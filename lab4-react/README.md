# Порядок выполнения лабораторной работы 4

## 1. Перейдите в папку лабораторной работы
```sh
cd lab4-react
```

## 2. Создайте свою ветку
```sh
git checkout -b student-{ваш_номер}-lab4
```

## 3. Допускается два способа сдачи работы.

### 3.1 Первый (аналогично лабораторным работам 1–3)
1. Создайте папку с решениями и скопируйте в неё папку с примером (`example`) или самостоятельно создайте папку `{project-name}` и необходимые файлы для задания внутри:
```sh
mkdir solutions/student-{ваш_номер}
cp -r tasks/example/* solutions/student-{ваш_номер}/
```
2. Выполните задание, выданное в файле `tasks/{ваш_номер}.md` (индивидуальные темы будут выданы преподавателем).
3. Закоммитьте и запушьте изменения:
```sh
git add solutions/student-{ваш_номер}/*
git commit -m "Lab 4 solution by student {номер}"
git push origin student-{ваш_номер}-lab4
```

### 3.2 Второй (свой репозиторий)
1. Создайте новый открытый репозиторий на GitHub `{project-name}` (название может отличаться, но должно отражать суть работы).
2. В репозитории создайте ветку `develop` и выполните работу в ней (создавать подпапку `{project-name}` не обязательно — можно работать в корне репозитория). Ветка `main` должна быть пустой, но допускается первичный коммит с базовым `README.md`.
3. Создайте пул-реквест с ветки `develop` на ветку `main`.
4. В ветке `student-{ваш_номер}-lab4` в папке `solutions/student-{ваш_номер}` создайте файл `solution.md` со ссылкой на пул-реквест.

## 4. Задание
Создайте библиотеку UI-компонентов и веб-приложение на React с примером применения созданных компонентов.

### Дополнительные базовые требования:
- Тип проекта должен быть `module`, использовать импорты и экспорты ES6. Ключевые слова `require`, `module.exports` — запрещены.
- `package.json` обоих проектов должен содержать команды `lint` и `lint:fix` в соответствии с примером.
- `package.json` обоих проектов должен содержать команды `test` и `test:coverage` в соответствии с примером.
- Язык разработки — TypeScript. Допускаются конфигурационные файлы jest, eslint на JS.
- Допустимые библиотеки и их версии — в соответствии с предложенным примером. Запрещено использование сторонних библиотек, в том числе UI, за исключением требуемых заданием.
- Папка с решением (репозиторий с решением) должна содержать только необходимые файлы. Папки `coverage`, `node_modules` должны быть проигнорированы.
- Скрипты запуска `build`, `dev`, `lint`, `test` должны проходить без ошибок.

### Нефункциональные требования:
- `eslint` должен быть настроен с требованиями не ниже требований примера, с отступами в виде 2 пробелов, запретом на лишние переносы строк и знаки `;`. Команда `npm run lint` должна проходить без вывода предупреждений и ошибок.
- Все написанные тесты должны проходить.
- Все переменные и функции должны быть типизированы, использование ключевого слова `any` — не разрешается.
- Coverage хотя бы одного разрабатываемого компонента должен быть не ниже 90% по всем столбцам.
- `README.md` должен содержать описание проекта, инструкцию по запуску, скрины с примерами работы приложения.
