# Порядок выполнения лабораторной работы 6

## 1. Перейдите в папку лабораторной работы
```sh
cd lab6-mvp
```

## 2. Создайте свою ветку
```sh
git checkout -b student-{ваш_номер}-lab6
```

## 3. Сдача работы

Лабораторная работа продолжает курсовой проект, поэтому выполняется в **собственном публичном репозитории** на GitHub. В репозитории заданий сдаётся только ссылка на пул-реквест курсовой работы.

1. В репозитории курсовой работы создайте ветку `lab6` от ветки `main` (если пул-реквест лабораторной 5 ещё не влит, допускается создать ветку `lab6` от ветки `lab5`) и выполняйте работу в ней.
2. Создайте пул-реквест с ветки `lab6` на ветку `main`.
3. В репозитории заданий `js_6310_labs_2026` в ветке `student-{ваш_номер}-lab6` создайте файл `solutions/student-{ваш_номер}/solution.md` со ссылкой на пул-реквест курсовой работы:
```sh
mkdir -p solutions/student-{ваш_номер}
```
```md
# Лабораторная работа 6

Ссылка на пул-реквест курсовой работы: {ссылка}
```
4. Закоммитьте и запушьте изменения, создайте пул-реквест с ветки `student-{ваш_номер}-lab6` в ветку `main`:
```sh
git add solutions/student-{ваш_номер}/solution.md
git commit -m "Lab 6 solution by student {номер}"
git push origin student-{ваш_номер}-lab6
```

## 4. Задание

Реализуйте Minimum viable product (MVP) курсового приложения в соответствии с файлом `mvp.md`, созданным в лабораторной работе 5.

1. Реализуйте основной сценарий (use case) из `mvp.md` полностью: от действия пользователя до ожидаемого результата.
2. Все страницы и компоненты, задействованные в основном сценарии, должны быть функциональны. Остальные страницы и компоненты могут оставаться заглушками.
3. Приложение должно запускаться и работать без ошибок в консоли и без необработанных исключений в рамках основного сценария.
4. Подготовьте демонстрацию основного сценария для защиты работы.
5. Обновите `README.md`: опишите MVP, порядок запуска и приложите скрины основного сценария.

### Дополнительные базовые требования

- Тип проекта должен быть `module`, использовать импорты и экспорты ES6. Ключевые слова `require`, `module.exports` — запрещены в исходном коде приложений (конфигурационные файлы jest и eslint могут быть на JS).
- `package.json` обоих проектов должен содержать команды `lint` и `lint:fix` в соответствии с примером.
- `package.json` обоих проектов должен содержать команды `test` и `test:coverage` в соответствии с примером.
- Язык разработки — TypeScript. Допускаются конфигурационные файлы jest и eslint на JS.
- Используемые библиотеки должны соответствовать списку из `architecture.md`. Добавление сторонних библиотек, не указанных в `architecture.md`, — по согласованию с преподавателем.
- Папка с решением (репозиторий с решением) должна содержать только необходимые файлы. Папки `coverage`, `node_modules` должны быть проигнорированы.
- Скрипты запуска `build`, `dev`, `lint`, `test` обоих проектов должны проходить без ошибок.
- В корне репозитория должны находиться файлы `architecture.md`, `mvp.md` и `README.md`.

### Нефункциональные требования

- `eslint` должен быть настроен с требованиями не ниже требований примера, с отступами в виде 2 пробелов, запретом на лишние переносы строк и знаки `;`. Команда `npm run lint` должна проходить без вывода предупреждений и ошибок.
- Все написанные тесты должны проходить.
- Все переменные и функции должны быть типизированы, использование ключевого слова `any` — не разрешается.
- Coverage хотя бы одного разрабатываемого компонента должен быть не ниже 90% по всем столбцам.
- `README.md` должен содержать описание проекта, инструкцию по запуску, скрины с примерами работы приложения.
