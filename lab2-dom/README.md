# Порядок выполнения лабораторной работы 2

## 1. Перейдите в папку лабораторной работы
```sh
cd lab2-dom
```

## 2. Создайте свою ветку
```sh
git checkout -b student-{ваш_номер}-lab2
```

## 3. Допускается два способа сдачи работы.

### 3.1 Первый (аналогично лабораторной работе 1)
1. Создайте папку с решениями и скопируйте в неё папку с примером (или самостоятельно создайте папку `style-plugin` и необходимые для задания файлы):
```sh
mkdir solutions/student-{ваш_номер}
cp -r tasks/style-plugin solutions/student-{ваш_номер}/
```
2. Выполните задание.
3. Закоммитьте и запушьте изменения:
```sh
git add solutions/student-{ваш_номер}/style-plugin/*
git commit -m "Lab 2 solution by student {номер}"
git push origin student-{ваш_номер}-lab2
```

### 3.2 Второй (свой репозиторий)
1. Создайте новый открытый репозиторий на GitHub, например `kai-style-plugin` (название может отличаться, но должно отражать суть работы).
2. В репозитории создайте ветку `develop` и выполните работу в ней (создавать подпапку `style-plugin` не обязательно — можно работать в корне репозитория). Ветка `main` должна быть пустой, но допускается первичный коммит с базовым `README.md`.
3. Создайте пул-реквест с ветки `develop` на ветку `main`.
4. В ветке `student-{ваш_номер}-lab2` в папке `solutions/student-{ваш_номер}` создайте файл `solution.md` со ссылкой на пул-реквест.

## 4. Задание
Создайте плагин для Google Chrome (Yandex Browser), меняющий стиль сайта kai.ru в соответствии с вашим вариантом. Список вариантов — [tasks/variants.md](tasks/variants.md), распределение вариантов в телеграмм чате.

### Функциональные требования
- На главную страницу должна быть добавлена кнопка, которая по нажатию меняет стиль страницы и отображает текущий статус стиля (включен/выключен).
- При перезагрузке страницы статус стиля должен сохраняться (используйте `localStorage` или другие варианты).
- Изменение стиля должно работать минимум на главной странице и одной странице из навигации.

### Нефункциональные требования
- Должно быть изменено не менее 8 стилей страницы (цвета шрифта, заливки, отступы, границы и прочее).
- В коде должны использоваться `getElementById`, `querySelector`, `querySelectorAll`, `parentElement`, `children`.
- Как минимум один из `querySelector` или `querySelectorAll` должен содержать сложный селектор (два класса, один класс и модификатор и прочее).
- Папка с решением (или репозиторий с решением) должны содержать файлы `manifest.json`, `content.js`, `readme.md` и папку `images` с примерами результатов.
- `README.md` должен содержать описание проекта, инструкцию по запуску, картинки с примерами.
- Бонус (не учитывается при оценке): попробуйте использовать классы CSS вместо прямого изменения стилей элемента.
