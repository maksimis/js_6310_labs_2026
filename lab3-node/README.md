# Порядок выполнения лабораторной работы 3

## 1. Перейдите в папку лабораторной работы
```sh
cd lab3-node
```

## 2. Создайте свою ветку
```sh
git checkout -b student-{ваш_номер}-lab3
```

## 3. Допускается два способа сдачи работы.

### 3.1 Первый (аналогично лабораторным работам 1 и 2)
1. Создайте папку с решениями и скопируйте в неё папку с примером (`example`):
```sh
mkdir solutions/student-{ваш_номер}
cp -r tasks/example/* solutions/student-{ваш_номер}/
```
2. Выполните задание, выданное в файле `tasks/{ваш_номер}.md` (индивидуальные темы будут выданы преподавателем).
3. Закоммитьте и запушьте изменения:
```sh
git add solutions/student-{ваш_номер}/*
git commit -m "Lab 3 solution by student {номер}"
git push origin student-{ваш_номер}-lab3
```

### 3.2 Второй (свой репозиторий)
1. Создайте новый открытый репозиторий на GitHub `{project-name}` (название может отличаться, но должно отражать суть работы).
2. В репозитории создайте ветку `develop` и выполните работу в ней (создавать подпапку `{project-name}` не обязательно — можно работать в корне репозитория). Ветка `main` должна быть пустой, но допускается первичный коммит с базовым `README.md`.
3. Создайте пул-реквест с ветки `develop` на ветку `main`.
4. В ветке `student-{ваш_номер}-lab3` в папке `solutions/student-{ваш_номер}` создайте файл `solution.md` со ссылкой на пул-реквест.

## 4. Задание
Создайте node package приложение в соответствии со своим заданием.

### Дополнительные базовые требования:
- Тип проекта должен быть `module`, использовать импорты и экспорты ES6. Ключевые слова `require`, `module.exports` — запрещены.
- `package.json` должен содержать команды `lint` и `lint:fix` в соответствии с примером.
- `package.json` должен содержать команды `test` и `test:coverage` в соответствии с примером.
- Настройки coverage должны быть не ниже, чем указанные в примере.
- Для передачи токена доступа должен использоваться `.env`. Наличие валидного токена в коде, в том числе в истории коммитов, — запрещено.
- Папка с решением (или репозиторий с решением) должна содержать только необходимые файлы. Папки `coverage`, `node_modules` должны быть проигнорированы.

### Нефункциональные требования:
- `eslint` должен быть настроен с требованиями не ниже требований примера, с отступами в виде 2 пробелов. Команда `npm run lint` должна проходить без вывода предупреждений и ошибок.
- Все тесты должны проходить.
- Coverage threshold должен быть соблюден.
- `README.md` должен содержать описание проекта, инструкцию по запуску, скрины с примерами работы приложения.
- При реализации бота ВКонтакте используйте библиотеку `vk-io`.
- При реализации телеграм-бота используйте библиотеки `node-telegram-bot-api` или `telegraf`.
- При реализации API используйте библиотеки `express` или `nestjs`.
- Пошаговые команды бота должны быть реализованы с помощью конечного автомата.
- Текущее состояние команд при запуске бота из различных пользователей не должно пересекаться (все команды должны выполняться независимо).
- Перезапуск бота или API может вызывать сброс состояния.
- Входящие запросы должны быть провалидированы, бот или API не должны падать при получении некорректных запросов.
- Бонус (не оценивается): перезапуск бота или API сохраняет состояние (используйте текстовые файлы (json или другой формат) или sqlite, но не переусложняйте проект).
